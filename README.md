# Task Manager API

CRUD API for tasks built with FastAPI, SQLModel, PostgreSQL, Redis and Alembic.

## Features

- Reusable `BaseTable` (`id`, `created_at`, `updated_at`) and a single `TaskStatus` enum
- Every response, including errors, uses the same `ApiResponse` shape
- Redis caching of `GET /tasks` and `GET /tasks/{id}`, cleared on create, update and delete
- `GET /cache` shows the cached keys (uses `SCAN`, only keys with the `tasks:` prefix)
- Alembic migrations autogenerated from the models and applied automatically in Docker

## Configuration

Settings come from environment variables (`.env`). Create it first:

```bash
cp .env.example .env
```

| Variable | Meaning |
|---|---|
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | Credentials for the Postgres container |
| `DATABASE_URL` | Used when running the app locally (default points to `localhost:5433`) |
| `REDIS_URL` | Used when running the app locally (default `localhost:6379`) |
| `CACHE_TTL` | Cache expiry in seconds (default 60) |
| `APP_PORT` | Host port for the API in Docker (default 8010) |

Inside Docker Compose, `DATABASE_URL` and `REDIS_URL` are overridden to use the service names `db` and `redis`.

## Run everything with Docker (one command)

```bash
cd task-manager-api          # must be run from the project root
cp .env.example .env
docker compose up -d --build
```

This starts Postgres, Redis and the API. The migration runs automatically before the server starts.

- API: http://localhost:**8010** (not 8000)
- Interactive docs: http://localhost:8010/docs
- Cache entries: http://localhost:8010/cache (empty until you call `GET /tasks` or `GET /tasks/{id}`)

> **If you see a different service (e.g. CRM) instead of this API:** you opened the wrong port. This app is published on `APP_PORT` (default **8010**); port 8000 is commonly used by other projects. Also make sure no other Docker stack is using ports 5433 or 6379 (`docker ps`), and always run `docker compose` from this project's folder.

Check it is running: `docker compose ps` and `docker compose logs -f app`.

Stop with `docker compose down` (add `-v` to delete the database volume too).

Compose publishes Postgres on host port **5433** and Redis on **6379**. If you started a standalone container with the same ports (see below), stop it first: `docker stop task-manager-db task-manager-redis`.

## Run locally (app on your machine, Postgres and Redis in Docker)

Run everything from the project root so `.env` is found.

**1. Create `.env`**

```bash
cp .env.example .env
```

**2. Create the virtual environment and install packages**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

**3. Start Postgres** (host port **5433**, to avoid clashing with a local Postgres on 5432)

```bash
docker run -d --name task-manager-db \
  -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=tasks \
  -p 5433:5432 -v task_manager_pgdata:/var/lib/postgresql/data \
  postgres:16-alpine
```

Check it is ready: `docker exec task-manager-db pg_isready -U postgres -d tasks`

The matching URL in `.env`:

```
DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5433/tasks
```

Next time just run `docker start task-manager-db`.

**4. Run the migration** (creates the `task` table)

```bash
alembic upgrade head
```

**5. Start Redis** (needed for caching)

```bash
docker run -d --name task-manager-redis -p 6379:6379 redis:7-alpine
```

**6. Start the API**

```bash
uvicorn app.main:app --reload --port 8010
```

**See the table**

```bash
docker exec task-manager-db psql -U postgres -d tasks -c '\dt'
docker exec task-manager-db psql -U postgres -d tasks -c '\d task'
docker exec task-manager-db psql -U postgres -d tasks -c 'SELECT * FROM task;'
```

**Stop / reset**

```bash
docker stop task-manager-db task-manager-redis
docker rm -f task-manager-db && docker volume rm task_manager_pgdata   # wipe the database
```

If you use your own Postgres or Redis instead of Docker, just change `DATABASE_URL` / `REDIS_URL` in `.env`.

## Endpoints

| Method | Path | Purpose | Success code |
|---|---|---|---|
| POST | `/tasks` | Create a task | 201 |
| GET | `/tasks` | List tasks (cached) | 200 |
| GET | `/tasks/{id}` | Get one task (cached) | 200 |
| PUT | `/tasks/{id}` | Update a task | 200 |
| DELETE | `/tasks/{id}` | Delete a task | 200 |
| GET | `/cache` | View cached entries | 200 |

Errors keep real status codes (404 not found, 422 validation, 500 unexpected).

Response shape:

```json
{ "success": true, "message": "Task created", "data": { "id": "..." }, "errors": null }
{ "success": false, "message": "Task not found", "data": null, "errors": ["Task not found"] }
```

Example:

```bash
curl -X POST localhost:8010/tasks -H 'content-type: application/json' \
  -d '{"title": "Write docs", "status": "in_progress"}'
```

`status` is one of `pending` (default), `in_progress`, `done`.

## Migrations

The migration in `alembic/versions/` was generated from the models. After changing a model:

```bash
alembic revision --autogenerate -m "describe change"
alembic upgrade head
```

Always read the generated file before committing it.

## Project layout

```
app/
  main.py          app + routers + exception handlers
  config.py        settings from environment
  database.py      engine and session dependency
  cache.py         Redis helpers (get / set / invalidate)
  enums.py         TaskStatus
  exceptions.py    global error handlers
  models/          BaseTable, Task
  schemas/         ApiResponse, TaskCreate/Update/Read, CacheEntry
  routers/         tasks, cache
alembic/           migrations
```
